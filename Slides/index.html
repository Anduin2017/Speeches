第三章：从基础聚类算法：直观理解 K-Means 开始

聚类算法的底层逻辑：K-Means

  • 航班旅客坐标系：X轴购票次数，Y轴平均价格
  • 数据落点分布：直觉分类散客 vs 高端商务客
  • 人类视觉天生擅长寻找“相似”和“聚集”

  • 概要：画一个 X-Y 坐标系，呈现出两组数据群。大家凭直觉就能看出它们分属两类。人类的视觉天生擅长寻找“相似”和“聚集”。

想象一下，我们现在有一个二维坐标系平面，画上 X 轴和 Y 轴。假设 X 轴代表一个旅客过去一年购买机票的“次数”，Y 轴代表他每次购买机票的“平均价格”。

现在，把我们虚拟的航空公司的一万个客户数据撒到这个坐标系里，每一个客户就是一个点。（这里的数据都是假的）

作为人类，你哪怕只是直观审视这张图，你的直觉立刻就会告诉你：这里大概有“两个聚落”人。左下角有一大聚落（买得少且便宜，可能是偶尔旅游的散客），右上角有一小聚落（买得多且贵，这是我们的高端商务常旅客）。或者说，我们可以快速从这个表里得到一个粗略的结论：经常乘坐飞机的人，往往消费能力也更强。

看，人类的视觉天生就十分擅长寻找“相似”和“聚集”。你不需要任何复杂的计算，一眼就能把客户分好类。

早期人工智能：K-Means 算法

“计算机不靠看，它靠算。”

\[d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}\]

  • 计算机通过“算距离”理解相似性（欧氏距离）
  • 随机设定中心点，循环算距离
  • 不断迭代寻找最佳分类聚落直到稳定

但是，计算机没有眼睛，它看不到“两个聚落”点。那计算机要怎么把这些客户分类呢？这时候，一种古老、简单，但又可以说是早期“人工智能”代表的算法登场了——它叫 K-Means（K-均值聚类）。

计算机不靠“看”，它靠“算”。它计算什么？计算点和点之间的直线距离。

借用最基础的平面几何概念，在二维平面上，两个点 \((x_1, y_1)\) 和 \((x_2, y_2)\) 之间的直线距离（在数学上叫欧氏距离），公式是这样的:

\[d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}\]

计算机的执行逻辑十分明确：它首先在空间中随机初始化两个聚合中心，随后对总体节点进行全局的距离计算以进行初步归属。谁离中心点 A 更近，谁就归属 A 类；谁离 B 近，就归属 B 类。分完之后，它再根据分好的群体重新找更准确的中心点，再算一遍距离。循环几次，直到一切稳定下来。

通过这种依赖严密测算的持续迭代机制，最终得出的机器分类结果与人类肉眼的直觉分类完全一致。

距离近的圈在一起，这就是计算机理解“相似性”的唯一方式。

跨越维度的鸿沟

  • 从两维到三维：年龄
  • 增加维度：餐食、航线、偏好…
  • 千维空间：人类大脑无法想象
  • 计算机：维度不是问题！

二维很好理解。现在，我们给这个坐标系加上一个 Z 轴，比如代表这个旅客的“年龄”。 \((x, y, z)\)，这是一个三维立体空间，我们的点悬浮在了半空中。没关系，人类的空间认知能力仍可理解，计算机也只需要在公式里再加一项即可。

接下来，我们需要进行一次逻辑上的推演。

如果我们再加一个维度，比如“偏好餐食（素食/肉食）”，再加一个“是否带小孩”，再加一个“常飞航线”，再加一千个、一万个描述这个旅客的特征……

到了四维、五维甚至一千维，我们人类的大脑就难以处理了，我们根本无法想象一个一千维的空间长什么样。对系统架构而言，维度的伸展并不会造成计算逻辑的本质差异。

计算机眼中的“相似”

高维距离与低维数学本质毫无区别。

\[d = \sqrt{\sum_{i=1}^{n} (x_i - y_i)^2}\]

简化为向量的差的模（长度）：

\[d = \| \mathbf{x} - \mathbf{y} \|\]

  • 维度延伸：特征完美统一转化为向量
  • 两向量差的模代表绝对的“相似度”

在计算机眼里，算 2 个数字的距离，和算 1000 个数字的距离，在数学本质上没有任何区别。它的距离公式无非就是变得更长了而已：

\[d = \sqrt{\sum_{i=1}^{n} (x_i - y_i)^2}\]

这个距离是两个点的欧氏距离。为了简化上面的公式，我们把它写成向量的形式：

\[d = \| \mathbf{x} - \mathbf{y} \|\]

可以看出，两个向量的距离，就是它们的差的模（长度）。这就是计算机理解“相似性”的方式。

第四章：万物皆可向量

把文字变成数字

4.1 给世界贴标签：博客文章的数字化实验

博客文章 空客 起飞 降落 波音 特征向量
第一篇 (A320起飞) 1 1 0 0 [1, 1, 0, 0]
第二篇 (737降落) 0 0 1 1 [0, 0, 1, 1]
第三篇 (起降原理) 0 1 1 0 [0, 1, 1, 0]


\[ d_{1,3} = \sqrt{(1-0)^2 + (1-1)^2 + (0-1)^2 + (0-0)^2} \approx 1.41 \]


\[ d_{1,2} = \sqrt{(1-0)^2 + (1-0)^2 + (0-1)^2 + (0-1)^2} = \sqrt{4} = 2 \]

为了更为直观地展示此项转化过程，我们从基础的人工标签分类开始。假设在我们航空公司的内部知识库里，我刚刚写了三篇短小精悍的博客。 现在，我来给它们手工打上标签（Tag）：第一篇讲的是 A320 的起飞，第二篇 737 的降落，第三篇飞机的起降原理。

假设我们的系统目前很简陋，一共只有 4 个维度的标签：空客、起飞、降落、波音。如果博客包含了这个标签，我们就记为 1，没有就记为 0。按照这个规则，我们的三篇博客瞬间就变成了空间里的三个向量。看，文字消失了，取而代之的是纯粹的数字。我们可以实际计算一下第一篇和第三篇之间的欧氏距离，距离是1.41。第一篇和第二篇的距离是2，所以计算机得出结论：第一篇和第三篇更相似，跟人类直觉完全一致。

4.2 欧氏距离的致命漏洞

如果此时混入一篇完全无关联的第四篇文章：“日常菜谱” [0, 0, 0, 0]：


\[ d_{1,4} = \sqrt{(1-0)^2 + (1-0)^2 + (0-0)^2 + (0-0)^2} \approx 1.41 \]


荒谬的推论：A320起飞与起降原理的距离，竟然等于与日常菜谱的距离！

看起来很完美，对吧？但是，假设此时，我们的知识库里混进了一篇完全无关联的第四篇文章：“日常菜谱制作”。它既没有空客，也没有波音，所以特征向量全是 0。 当我们算一下，第一篇（A320的起飞）和这篇（日常菜谱）之间的欧氏距离：结果竟然也是 1.41！ 这里存在一个明显的逻辑漏洞。第一篇和第三篇的距离是 1.41，第一篇和第四篇也是 1.41！如果计算机死板地依靠欧氏距离，它会十分愚蠢地告诉你：相关性是一模一样的！此时系统将完全不可用。问题究竟出在哪里？

问题在于：欧氏距离无法真正反映“相关性”。 在欧氏距离的计算公式里，你因为“拥有一个不同的特征”所产生的距离，和你“缺失一个特征”所产生的距离，在数学上被等同对待了。这在处理高维稀疏特征时，是一场灾难。

4.3 换个角度看世界：点乘与余弦

向量点乘 (内积)

把它俩相同维度上的数字两两相乘，然后再全部加起来。

A320起飞 \(\cdot\) 起降原理 \(1\times0 + 1\times1 + 0\times1 + 0\times0 = 1\) 有交集！

A320起飞 \(\cdot\) 日常菜谱 \(1\times0 + 1\times0 + 0\times0 + 0\times0 = 0\) 毫不相干！

余弦相似度 (Cosine Similarity)

\[ \mathbf{x} \cdot \mathbf{y} = \|\mathbf{x}\| \|\mathbf{y}\| \cos(\theta) \]

\[ \cos(\theta) = \frac{\mathbf{x} \cdot \mathbf{y}}{\|\mathbf{x}\| \|\mathbf{y}\|} \]

  • \(\theta = 0^\circ \Rightarrow \cos(0^\circ) = 1\) (绝对契合)
  • \(\theta = 90^\circ \Rightarrow \cos(90^\circ) = 0\) (完全不相关)

为了解决欧氏距离的致命漏洞，我们要回忆一下高中数学里的另一个核心概念：向量的点乘（内积）。 什么是点乘？最直白的理解，点乘就是把两个向量在相同维度上的数字两两相乘，然后再全加起来。我们用点乘来重新审视一下刚才的三篇文章： A320起飞 [1, 1, 0, 0] 与 起降原理 [0, 1, 1, 0] 的点乘结果是 1（结果大于 0，说明它们在某个维度上有共鸣，产生了交集！） A320起飞 [1, 1, 0, 0] 与 日常菜谱 [0, 0, 0, 0] 的点乘结果是 0（结果是 0，说明它们无论怎么乘，都不会产生实质相关性，判定为毫不相干！） 由此可见，仅通过转换数学运算方式，日常菜谱就被系统完美地筛选排除。

在高中数学里，两个向量的点乘，在几何上有一个优美的公式。把长度除过去，我们就得到了现代人工智能评估相似度最核心的公式——余弦相似度 (Cosine Similarity)。只要我们抛弃绝对的直线距离，转而去计算夹角余弦，“日常菜谱”的误判就永远不会发生了。

4.4 终极技术：L2 归一化

强行把所有向量的长度变成 1（投射到“单位超球面”上）


第一，关于点乘

把长度为 1 代入公式：

\[ \mathbf{x} \cdot \mathbf{y} = 1 \times 1 \times \cos(\theta) = \cos(\theta) \]

单位超球面上：点乘直接等于余弦！

第二，关于欧氏距离

运用余弦定理展开：

\[ d^2 = \|\mathbf{x}\|^2 + \|\mathbf{y}\|^2 - 2(\mathbf{x} \cdot \mathbf{y}) \]

\[ d = \sqrt{2 - 2\cos(\theta)} \]

殊途同归：无论欧氏距离还是夹角，全被完美地统一在了一起

讲到这里，大家可能会问：欧氏距离，夹角余弦，点乘。这三个东西在写代码时要切来切去吗？这不符合计算机的美学。于是，AI 工程师们施展了最巧妙的一招：L2 归一化 (L2 Normalization)。 既然向量的“长度”会干扰计算，那我们就强行把所有向量长度变成 1。这相当于把它们全拉伸投射到一个“单位超球面”的表面上。 我们看看实际效果：模长全是 1 后，点乘由于长度全为1，所以点乘直接等于夹角余弦！而欧氏距离展开后也变成了 \(d = \sqrt{2 - 2\cos(\theta)}\)。 殊途同归！在完成了 L2 归一化之后，无论你是算点乘、算余弦相似度、还是算欧氏距离，在数学本质上已经是完全等价的了！这就是大一统。这就叫架构的工程美学，底层全统一。

重新审视：“日常菜谱”的被严谨隔离

在我们这个极简的 4 维模型（并且强制长度为 1）里：

点乘直接等于 0！
夹角 \(\theta = 90^\circ\)，\(\cos(90^\circ) = 0\)
它们没有任何交集，判定为完全不相关。

针对刚才日常菜谱的分类误判，我们现在以点乘运算进行检验：点乘直接等于 0！ 这是因为两个特征向量在多维空间里完全垂直，夹角成了 90 度，毫无交集，被瞬间判断为完全不相关。干净利落。 但在真实的大模型中，由于捕捉标点和通用语法，极少出现绝对的正交，但距离依旧极其遥远，等会我们看看大模型怎么判断的。

从离散标签到连续向量空间

5.1 词嵌入矩阵 (Embedding Matrix)：超级词典

  • 突破：机器自主阅读海量文本
  • 摆脱人类主观标签的束缚
  • 每个词语分配为精确的1024维坐标
  • 语义相近 \(\Rightarrow\) 空间距离无限缩短

在上一章中，我们演示了如何通过人工提取“空客”、“降落”等 4 个离散标签，将文本转化为 [1, 0, 1, 0] 这样的二进制特征向量。但思考一下：一本波音 737 的 FCOM 飞行手册有几千页，如果让人类给每一页手工打标签，那将消耗极大的人力和时间。而且人类的主观性太强——有人标记“襟翼”，有人标记“增升装置”，有人用“flap”，同一个概念被叫了三个名字，系统就乱套了。

现代 AI 的核心突破，就是让机器自己读完海量的文字，自己去发现词语之间的关系，自己构建出那个精确的 1024 维坐标体系。完全不需要人员去打标签。

您可以将 AI 训练阶段看作是一台全天候运转的机器，面前堆满了人们积累的网页、书籍、论文、手册等。它的任务便是：反复阅读计算，最终对每一个词在什么上下文出现、和哪些词搭配，形成一种精细的数据分布。这就是词嵌入矩阵（Embedding Matrix）。你可以把它想象成一本极其庞大的超级词典。它告诉系统的不是文字解释，而是一个精确的 1024 维坐标——就好比给每个词加了极其精确的定位。

词嵌入的深层数学表现


绝对正交的编号状态： \[ \mathbf{x}_{ ext{飞机}} \cdot \mathbf{x}_{ ext{苹果}} = 0 \quad ext{与} \quad \mathbf{x}_{ ext{飞机}} \cdot \mathbf{x}_{ ext{航空器}} = 0 \]


精密坐标映射 (Embedding Matrix)： \[ \mathbf{e}_i = E \cdot \mathbf{x}_i \quad (E \in \mathbb{R}^{1024 imes |V|}) \]

在数学上，这个过程是这样的：AI 系统维护着一个庞大的词汇表。在最原始的状态下，每个词只是一个互不相干的编号。“飞机”的关系和“苹果”没有任何区别，它们点乘的结果为零。

但经过疯狂地阅读文本后，AI 自行学习出了一个致密的权重矩阵。当“飞机”这个词被输入时，矩阵 \(E\) 就像一台精密的坐标转换仪，瞬间把它从一个无意义的编号，投射成一个拥有 1024 个数字的稠密坐标。在这个由 AI 自主构建的高维空间里——语义相近的词，坐标自动靠近。最终“飞机”和“航空器”的余弦相似度高达 0.95，可以说是几乎重叠了。没人专门教它飞机和航空器是同义词，它完全是通过计算百亿次数据得出的客观规律。

5.2 上下文突破：自注意力机制 (Self-Attention)

  • 静态词典的局限：每词一坐标，无法处理多义词
  • 核心方案：词语的意思，由周遭的“邻居”决定
  • 自注意力机制 (Self-Attention)：捕捉环境动态跳跃
  • 犹如百通道的大型调音台调整权重

刚才我们讲的超级词典有一个问题：每个词只有一个固定的坐标。但是中文里同一个字，在不同的句子里意思可能完全不同。比如“天空很蓝”里的“空”是sky、“空航班”是empty，而如果提问“空飞机多重？”指的是航空里的“空机重量”。如果赋予固定的平均位置，将严重失真。

解决方案是：看邻居。这就是 Transformer 架构的核心秘密：自注意力机制（Self-Attention）。您可以想象一个拥有 1024 根通道的超级调音台。当“空”进入时，它是模糊的。随后，该字向句子里的每一个邻居发出电波——“谁和我有关联联？”。“飞机”产生极强回波，“多重”也强烈响应。于是推子发生剧烈移动：代表“空机重量”的信号被推高，代表“天空”或“空闲”的被压到底。瞬间完成了它在 1024 维矩阵中的物理跳跃，稳稳锁定“无载客重量”的正确位置。

自注意力机制的核心数学原理

提问者（Query）、被查询者（Key）、信息载体（Value）： \[ Q = XW^Q, \quad K = XW^K, \quad V = XW^V \]


核心注意力分配矩阵： \[ ext{Attention}(Q, K, V) = ext{softmax}\left( rac{QK^T}{\sqrt{d_k}} ight)V \]


按概率吸收邻居特征： \[ \mathbf{z}_{ ext{空}} pprox 0.6 \cdot \mathbf{v}_{ ext{飞机}} + 0.3 \cdot \mathbf{v}_{ ext{多重}} + 0.1 \cdot \mathbf{v}_{ ext{其他}} \]

以下简要展示此技术的数学公式本质。Transformer 把每个词同时投影成三个角色：提问者（Query）、被查询者（Key）和信息载体（Value）。

简略而言就是三步：第一步是打分（\(QK^T\)）。“空”字对所有邻接词发出演算，经过点积，“飞机”和“多重”得分极高。第二步是分配权重，通过 $ ext{softmax}$ 计算百分比占比。第三步是吸收特征，根据这套比例，“空”字吸收了大量的飞机和多重信息。简言之，Transformer 是一套极其精准地计算上下文以改变词语空间指向的技术系统。

5.3 宏观浓缩：池化技术 (Pooling)

  • 现状困境：一万字的手册，就会产生一万个独立坐标
  • 终极需求：整合成单一坐标点以便文本比对
  • 落地手段：池化操作 (Pooling) - 均值或 [CLS]
  • 大一统：万物坍缩为 1024 维度的精确定点

现在我们遇到了最后一个实际问题。经过自注意力机制运算后，一篇一万字的 737 FCOM 手册，系统手里也就有了一万个坐标点。但是我们系统最终的任务是比对整篇文章的相似度，因此必须将一篇文章压缩成一个坐标。

这类似于评估航线整体经济性，各种独立参数必须压成一个整体报表数据。在应用里，这个操作被称为池化（Pooling）。最直接的做法就是：把所有词类的坐标取个平均值。或者让模型在顶端指定出一个能代表全文核心特征的池化位标识，即 [CLS] 池化。最终目的，都是把整片文字坍缩成唯一的点。

5.4 让 AI 落地的三大算力绝招

  • 痛点：算力高昂，大型企业部署成本高企
  • 蒸馏 (Distillation)：千亿参数传递小模型，降本增效
  • 量化 (Quantization)：INT4 无损式数字格式精度压缩，体积暴降 70%
  • MoE (混合专家)：拆除全局常驻计算，由路由器瞬切专属微型模块，极端省电

这种技术架构可能会引起顾虑：是否意味着需要部署异常高昂并占用超强算力的计算中心？其实，为了让其低成本下落，工程师研发了三大核心绝技。

第一个是蒸馏（Distillation）。即让昂贵的千亿参数模型充当指导对象，转移逻辑给廉价小模型。只要业务单一深入，其效能几无折损且体积极小。

第二个是量化（Quantization）。把内部精度很深的浮点格式强制压缩为占用极小的格式，如 INT4 量化。这虽然轻微妥协了理论极值精度，但却换取了近七成的体积缩减，使得商用落地大大提速。

最后则是大模型架构的颠覆：MoE（混合专家模型）。一改全局计算造成的极其耗电费时的“稠密模型”缺点，采用了稀疏结构。如同外包公司——针对不同内容只通电并唤醒特定的模块专家运算。上述“三板斧”直接为极低成本全覆盖的企业级运行奠定了底层商业底气。
