# 第三章：从基础聚类算法：直观理解 K-Means 开始

## 聚类算法的底层逻辑：K-Means

:::::::::::::: {.columns}
::: {.column width="50%"}
::: {.incremental}
- 航班旅客坐标系：X轴购票次数，Y轴平均价格
- 数据落点分布：直觉分类散客 vs 高端商务客
- 人类视觉天生擅长寻找“相似”和“聚集”
:::
:::
::: {.column width="50%"}
![](Pics/Scatter_Plot_Clustering.png)
:::
::::::::::::::

::: notes
* **概要**：画一个 X-Y 坐标系，呈现出两组数据群。大家凭直觉就能看出它们分属两类。人类的视觉天生擅长寻找“相似”和“聚集”。

想象一下，我们现在有一个二维坐标系平面，画上 X 轴和 Y 轴。假设 X 轴代表一个旅客过去一年购买机票的“次数”，Y 轴代表他每次购买机票的“平均价格”。

现在，把我们虚拟的航空公司的一万个客户数据撒到这个坐标系里，每一个客户就是一个点。（这里的数据都是假的）

作为人类，你哪怕只是直观审视这张图，你的直觉立刻就会告诉你：这里大概有“两个聚落”人。左下角有一大聚落（买得少且便宜，可能是偶尔旅游的散客），右上角有一小聚落（买得多且贵，这是我们的高端商务常旅客）。或者说，我们可以快速从这个表里得到一个粗略的结论：经常乘坐飞机的人，往往消费能力也更强。

看，人类的视觉天生就十分擅长寻找“相似”和“聚集”。你不需要任何复杂的计算，一眼就能把客户分好类。
:::

## 早期人工智能：K-Means 算法

:::::::::::::: {.columns}
::: {.column width="50%"}
> "计算机不靠看，它靠算。"

$$d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$$

::: {.incremental}
- 计算机通过“算距离”理解相似性（欧氏距离）
- 随机设定中心点，循环算距离
- 不断迭代寻找最佳分类聚落直到稳定
:::
:::
::: {.column width="50%"}
![](Pics/K_Means_Clustering_Algorithm_Steps.png)
:::
::::::::::::::

::: notes
但是，计算机没有眼睛，它看不到“两个聚落”点。那计算机要怎么把这些客户分类呢？这时候，一种古老、简单，但又可以说是早期“人工智能”代表的算法登场了——它叫 K-Means（K-均值聚类）。

计算机不靠“看”，它靠“算”。它计算什么？计算点和点之间的直线距离。

借用最基础的平面几何概念，在二维平面上，两个点 $(x_1, y_1)$ 和 $(x_2, y_2)$ 之间的直线距离（在数学上叫欧氏距离），公式是这样的:

$$d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$$

计算机的执行逻辑十分明确：它首先在空间中随机初始化两个聚合中心，随后对总体节点进行全局的距离计算以进行初步归属。谁离中心点 A 更近，谁就归属 A 类；谁离 B 近，就归属 B 类。分完之后，它再根据分好的群体重新找更准确的中心点，再算一遍距离。循环几次，直到一切稳定下来。

通过这种依赖严密测算的持续迭代机制，最终得出的机器分类结果与人类肉眼的直觉分类完全一致。

距离近的圈在一起，这就是计算机理解“相似性”的唯一方式。
:::

## 跨越维度的鸿沟

:::::::::::::: {.columns}
::: {.column width="50%"}
::: {.incremental}
- 从两维到三维：年龄
- 增加维度：餐食、航线、偏好...
- 千维空间：人类大脑无法想象
- 计算机：维度不是问题！
:::
:::
::: {.column width="50%"}
![](Pics/Machine_Learning_Terms_Embedding_Space_3D.png)
:::
::::::::::::::

::: notes
二维很好理解。现在，我们给这个坐标系加上一个 Z 轴，比如代表这个旅客的“年龄”。 $(x, y, z)$，这是一个三维立体空间，我们的点悬浮在了半空中。没关系，人类的空间认知能力仍可理解，计算机也只需要在公式里再加一项即可。

接下来，我们需要进行一次逻辑上的推演。

如果我们再加一个维度，比如“偏好餐食（素食/肉食）”，再加一个“是否带小孩”，再加一个“常飞航线”，再加一千个、一万个描述这个旅客的特征……

到了四维、五维甚至一千维，我们人类的大脑就难以处理了，我们根本无法想象一个一千维的空间长什么样。**对系统架构而言，维度的伸展并不会造成计算逻辑的本质差异。**
:::

## 计算机眼中的“相似”

:::::::::::::: {.columns}
::: {.column width="50%"}
> 高维距离与低维数学本质毫无区别。

$$d = \sqrt{\sum_{i=1}^{n} (x_i - y_i)^2}$$

简化为向量的差的模（长度）：

$$d = \| \mathbf{x} - \mathbf{y} \|$$

::: {.incremental}
- 维度延伸：特征完美统一转化为向量
- 两向量差的模代表绝对的“相似度”
:::
:::
::: {.column width="50%"}
![](Pics/What_Are_Embeddings_Vector_Space.webp)
:::
::::::::::::::

::: notes
在计算机眼里，算 2 个数字的距离，和算 1000 个数字的距离，在数学本质上**没有任何区别**。它的距离公式无非就是变得更长了而已：

$$d = \sqrt{\sum_{i=1}^{n} (x_i - y_i)^2}$$

这个距离是两个点的欧氏距离。为了简化上面的公式，我们把它写成向量的形式：

$$d = \| \mathbf{x} - \mathbf{y} \|$$

可以看出，两个向量的距离，就是它们的差的模（长度）。这就是计算机理解“相似性”的方式。

:::

## 4.1 给世界贴标签：博客文章的数字化实验

::: {.fragment}
| 博客文章 | 空客 | 起飞 | 降落 | 波音 | 特征向量 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **第一篇 (A320起飞)** | 1 | 1 | 0 | 0 | `[1, 1, 0, 0]` |
| **第二篇 (737降落)** | 0 | 0 | 1 | 1 | `[0, 0, 1, 1]` |
| **第三篇 (起降原理)** | 0 | 1 | 1 | 0 | `[0, 1, 1, 0]` |
:::

::: {.fragment}
<br>

$$ d_{1,3} = \sqrt{(1-0)^2 + (1-1)^2 + (0-1)^2 + (0-0)^2} \approx 1.41 $$
:::

::: {.fragment}
<br>

$$ d_{1,2} = \sqrt{(1-0)^2 + (1-0)^2 + (0-1)^2 + (0-1)^2} = \sqrt{4} = 2 $$
:::

::: notes
为了更为直观地展示此项转化过程，我们从基础的人工标签分类开始。假设在我们航空公司的内部知识库里，我刚刚写了三篇短小精悍的博客。
现在，我来给它们手工打上标签（Tag）：第一篇讲的是 A320 的起飞，第二篇 737 的降落，第三篇飞机的起降原理。

假设我们的系统目前很简陋，一共只有 4 个维度的标签：空客、起飞、降落、波音。如果博客包含了这个标签，我们就记为 1，没有就记为 0。按照这个规则，我们的三篇博客瞬间就变成了空间里的三个向量。看，文字消失了，取而代之的是纯粹的数字。我们可以实际计算一下第一篇和第三篇之间的欧氏距离，距离是1.41。第一篇和第二篇的距离是2，所以计算机得出结论：第一篇和第三篇更相似，跟人类直觉完全一致。

## 4.2 欧氏距离的致命漏洞

::: {.fragment}
如果此时混入一篇完全无关联的第四篇文章：“**日常菜谱**” `[0, 0, 0, 0]`：
:::

::: {.fragment}
<br>

$$ d_{1,4} = \sqrt{(1-0)^2 + (1-0)^2 + (0-0)^2 + (0-0)^2} \approx 1.41 $$
:::

::: {.fragment}
<br>

::: {style="font-size: 1.2em; text-align: center; color: red;"}
**荒谬的推论：A320起飞与起降原理的距离，竟然等于与日常菜谱的距离！**
:::
:::

::: notes
看起来很完美，对吧？但是，假设此时，我们的知识库里混进了一篇完全无关联的第四篇文章：“日常菜谱制作”。它既没有空客，也没有波音，所以特征向量全是 0。
当我们算一下，第一篇（A320的起飞）和这篇（日常菜谱）之间的欧氏距离：结果竟然也是 1.41！
这里存在一个明显的逻辑漏洞。第一篇和第三篇的距离是 1.41，第一篇和第四篇也是 1.41！如果计算机死板地依靠欧氏距离，它会十分愚蠢地告诉你：相关性是一模一样的！此时系统将完全不可用。问题究竟出在哪里？

问题在于：**欧氏距离无法真正反映“相关性”。** 在欧氏距离的计算公式里，你因为“拥有一个不同的特征”所产生的距离，和你“缺失一个特征”所产生的距离，在数学上被等同对待了。这在处理高维稀疏特征时，是一场灾难。
:::

## 4.3 换个角度看世界：点乘与余弦

:::::::::::::: {.columns}
::: {.column width="50%"}
::: {.fragment}
**向量点乘 (内积)**

把它俩相同维度上的数字两两相乘，然后再全部加起来。
<br><br>
**A320起飞** $\cdot$ **起降原理**
$1\times0 + 1\times1 + 0\times1 + 0\times0 = 1$
<span style="color: green;">有交集！</span>
<br><br>
**A320起飞** $\cdot$ **日常菜谱**
$1\times0 + 1\times0 + 0\times0 + 0\times0 = 0$
<span style="color: red;">毫不相干！</span>
:::
:::

::: {.column width="50%"}
::: {.fragment}
**余弦相似度 (Cosine Similarity)**

$$ \mathbf{x} \cdot \mathbf{y} = \|\mathbf{x}\| \|\mathbf{y}\| \cos(\theta) $$
<br>

$$ \cos(\theta) = \frac{\mathbf{x} \cdot \mathbf{y}}{\|\mathbf{x}\| \|\mathbf{y}\|} $$
<br>

* $\theta = 0^\circ \Rightarrow \cos(0^\circ) = 1$ (绝对契合)
* $\theta = 90^\circ \Rightarrow \cos(90^\circ) = 0$ (完全不相关)
:::
:::
::::::::::::::

::: notes
为了解决欧氏距离的致命漏洞，我们要回忆一下高中数学里的另一个核心概念：**向量的点乘（内积）**。
什么是点乘？最直白的理解，点乘就是把两个向量在相同维度上的数字两两相乘，然后再全加起来。我们用点乘来重新审视一下刚才的三篇文章：
A320起飞 [1, 1, 0, 0] 与 起降原理 [0, 1, 1, 0] 的点乘结果是 1（结果大于 0，说明它们在某个维度上有共鸣，产生了交集！）
A320起飞 [1, 1, 0, 0] 与 日常菜谱 [0, 0, 0, 0] 的点乘结果是 0（结果是 0，说明它们无论怎么乘，都不会产生实质相关性，判定为毫不相干！）
由此可见，仅通过转换数学运算方式，日常菜谱就被系统完美地筛选排除。

在高中数学里，两个向量的点乘，在几何上有一个优美的公式。把长度除过去，我们就得到了现代人工智能评估相似度最核心的公式——**余弦相似度 (Cosine Similarity)**。只要我们抛弃绝对的直线距离，转而去计算**夹角余弦**，“日常菜谱”的误判就永远不会发生了。
:::

## 4.4 终极技术：L2 归一化

::: {.fragment}
::: {style="font-size: 1.2em; text-align: center;"}
**强行把所有向量的长度变成 1（投射到“单位超球面”上）**
:::
:::

<br>

:::::::::::::: {.columns}
::: {.column width="50%"}
::: {.fragment}
**第一，关于点乘**

把长度为 1 代入公式：

$$ \mathbf{x} \cdot \mathbf{y} = 1 \times 1 \times \cos(\theta) = \cos(\theta) $$ 

<span style="color: blue;">单位超球面上：点乘直接等于余弦！</span>
:::
:::

::: {.column width="50%"}
::: {.fragment}
**第二，关于欧氏距离**

运用余弦定理展开：

$$ d^2 = \|\mathbf{x}\|^2 + \|\mathbf{y}\|^2 - 2(\mathbf{x} \cdot \mathbf{y}) $$

$$ d = \sqrt{2 - 2\cos(\theta)} $$
:::
:::
::::::::::::::

::: {.fragment}
::: {style="margin-top: 1.5em; text-align: center; color: green;"}
**殊途同归：无论欧氏距离还是夹角，全被完美地统一在了一起**
:::
:::

::: notes
讲到这里，大家可能会问：欧氏距离，夹角余弦，点乘。这三个东西在写代码时要切来切去吗？这不符合计算机的美学。于是，AI 工程师们施展了最巧妙的一招：L2 归一化 (L2 Normalization)。
既然向量的“长度”会干扰计算，那我们就强行把所有向量长度变成 1。这相当于把它们全拉伸投射到一个“单位超球面”的表面上。
我们看看实际效果：模长全是 1 后，点乘由于长度全为1，所以点乘直接等于夹角余弦！而欧氏距离展开后也变成了 $d = \sqrt{2 - 2\cos(\theta)}$。
殊途同归！在完成了 L2 归一化之后，无论你是算点乘、算余弦相似度、还是算欧氏距离，在数学本质上已经是完全等价的了！这就是大一统。这就叫架构的工程美学，底层全统一。
:::

::: notes
以下简要展示此技术的数学公式本质。Transformer 把每个词同时投影成三个角色：提问者（Query）、被查询者（Key）和信息载体（Value）。

简略而言就是三步：第一步是打分（$QK^T$）。“空”字对所有邻接词发出演算，经过点积，“飞机”和“多重”得分极高。第二步是分配权重，通过 $	ext{softmax}$ 计算百分比占比。第三步是吸收特征，根据这套比例，“空”字吸收了大量的飞机和多重信息。简言之，Transformer 是一套极其精准地计算上下文以改变词语空间指向的技术系统。
:::

## 5.3 宏观浓缩：池化技术 (Pooling)

:::::::::::::: {.columns}

这类似于评估航线整体经济性，各种独立参数必须压成一个整体报表数据。在应用里，这个操作被称为池化（Pooling）。最直接的做法就是：把所有词类的坐标取个平均值。或者让模型在顶端指定出一个能代表全文核心特征的池化位标识，即 [CLS] 池化。最终目的，都是把整片文字坍缩成唯一的点。

## 5.4 让 AI 落地的三大算力绝招

:::::::::::::: {.columns}
::: {.column width="50%"}
::: {.incremental}
- 痛点：算力高昂，大型企业部署成本高企
- **蒸馏 (Distillation)**：千亿参数传递小模型，降本增效
- **量化 (Quantization)**：INT4 无损式数字格式精度压缩，体积暴降 70%
- **MoE (混合专家)**：拆除全局常驻计算，由路由器瞬切专属微型模块，极端省电
:::
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
这种技术架构可能会引起顾虑：是否意味着需要部署异常高昂并占用超强算力的计算中心？其实，为了让其低成本下落，工程师研发了三大核心绝技。

第一个是蒸馏（Distillation）。即让昂贵的千亿参数模型充当指导对象，转移逻辑给廉价小模型。只要业务单一深入，其效能几无折损且体积极小。

第二个是量化（Quantization）。把内部精度很深的浮点格式强制压缩为占用极小的格式，如 INT4 量化。这虽然轻微妥协了理论极值精度，但却换取了近七成的体积缩减，使得商用落地大大提速。

最后则是大模型架构的颠覆：MoE（混合专家模型）。一改全局计算造成的极其耗电费时的“稠密模型”缺点，采用了稀疏结构。如同外包公司——针对不同内容只通电并唤醒特定的模块专家运算。上述“三板斧”直接为极低成本全覆盖的企业级运行奠定了底层商业底气。
:::

在准备今天的演示之前，我写了一段只有 50 行的自动化转换代码。这段代码做了一件高度精确的重构工作：

2024年初，Sora 的出现让我们惊呼不可思议。到了今天，随着国产力量的异军突起，比如 2025 年 2 月才发布的 **Kling 3.0 (快手可灵)** 和阿里的开源巨作 **Wan 2.2 (万相)** 模型，甚至刚刚发布的**Sora 1.0 (其实算是2.0了)**。这一切不再是一串冰冷的代码模型，而是已经进化成了**好莱坞级别的影视工业化生产线。**

这不仅仅是“把静态图片动起来”这么简单，它们在极速逼近一个令人敬畏甚至毛骨悚然的本质——**理解并重构物理规律。**

## 6.4 双塔奇谋：个性化推荐的核心机制

:::::::::::::: {.columns}
::: {.column width="50%"}

- **1024维内容向量 (Item 塔)**：表征商品、短视频与服务特性
- **低延迟距离计算**：在庞大维度空间中进行几何距离匹配推荐
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
既然一段文本、一张照片都可以变成多维宇宙里的一个坐标点，那我们顺理成章地推导出一个更加疯狂的想法：**如果把我们人类自己，也变成一个向量呢？**

各位平时刷抖音、看 B 站或者用 Netflix，是不是总有一种“它怎么这么懂我”、“它怎么知道我刚好想看这个”的惊讶感？今天，我就用高中几何的逻辑，给大家揭秘这个价值万亿美元的商业机密。

在工业界，这被称为**“双塔模型（Two-Tower Model）”**。

想象一个巨大无比的 1024 维宇宙：
* **右边的一座塔（Item 塔）**：系统用我们刚才讲的提取技术，把每一条短视频（或者我们航空公司的每一条辅营产品、每一个升舱优惠）都提取成了一个 1024 维的**内容向量**。
* **左边的一座塔（User 塔）**：系统为你这个用户，也分配了一个 1024 维的**用户向量**。代表了你的年龄、消费力、浏览习惯。

当你打开手机 APP 的那一瞬间，底层到底发生了什么？没有任何神秘的技术，也没有成千上万个审核员在后台盯着你。系统只是做了一次冷酷的数学运算：**拿着你的“用户向量”坐标，去那个包含了一亿个“视频向量”的空间里，算一次距离。**

系统画了一个圈，把离你坐标最近的 100 个视频捞出来，按距离由近到远排个序，展现在你的手机屏幕上。这就是所谓的“精准推荐”。
:::

## 6.5 意图传染：图神经网络(GNN)的消息传递

:::::::::::::: {.columns}
::: {.column width="50%"}
- **双向权重叠加**：行为触发向量坐标动态偏移
- **用户特征演化**：吸收特定内容属性（如趋向“航空极客”）
- **内容特征演化**：吸收用户群体属性（如绑定“高净值人群”）
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
通常会引出一个问题：视频的向量是固定的，那我的“用户向量”是怎么来的？它怎么知道我喜欢看航空航天的视频？这就涉及到了 AI 领域另一个优美的概念：**图神经网络（GNN）中的消息传递（Message Passing）**。

在这个多维宇宙里，向量并不是静止的死物。当你在这个平台上看了一个关于“波音 737 模拟器”的视频，并且点了个赞，在图论的数学模型中，你和这个视频之间就产生了一条引力连线。

* **用户被传染**：系统会把这个视频的 1024 维特征，按一定的权重“叠加”到你自己的特征向量上。你的坐标向着“硬核、航空极客”的方向发生了偏移。
* **视频被传染**：同时，你身上的特征（比如“男性”、“30岁”、“高净值”）也会叠加到这个视频的向量上。视频的坐标也发生了微妙的移动。

经过成千上万次这样的双向叠加，奇妙的化学反应发生了！如果明天有一个和你相似的“高净值”用户注册了平台，哪怕他这辈子没看过任何飞机视频，当系统计算距离时，会惊奇地发现：那个吸收了大量此类用户特征的“737 模拟器”视频，在坐标系上距离这个新用户很近！于是，系统成功地完成了一次跨界的精准推荐。

这就是算法比你更懂你的根本原因——**你的每一次点击、每一次停留，都在改变你在多维宇宙中的绝对坐标；而你，又在不知不觉中，把你的偏好传染给了你看过的内容。**
:::

## 6.6 冷启动挑战与解决路径

:::::::::::::: {.columns}

- **基于 Transformer 预提早定位**：
  - 解析多模态底层物理特征
  - 提取初始 1024 维向量坐标
  - 依靠内容实质关联种子用户
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
逻辑讲到这里完美，但在真实的商业落地中，我们会面临一个巨大的工程痛点：**冷启动（Cold Start）**。如果在我们的航班系统里，刚刚上线了一条全新的航线；或者在视频网站上，一个新人刚刚上传了一条没有任何播放量的视频。

没有用户看过它，它就没有被“传染”过，它的坐标是空的。这就意味着它永远无法进入任何人的推荐圈里，怎么办？这时候，就轮到我们第五章讲过的 **Transformer**再次登场了。

工业界的做法是：纯靠“内涵”强行打底。既然这个新视频没有播放数据，那系统就直接提取它的原始物理特征。用 Transformer 看一遍它的标题，用视觉模型看一遍它的封面，通过深层矩阵乘法计算，**提取**出其初始的 1024 维特征向量。

也就是说，这个视频一出生，系统就已经根据它的“长相和气质”，把它像空投一样，精准地投递到了 1024 维空间中属于它的那个街区。它不需要等别人来看它，它诞生那一刻的坐标，就已经决定了它会被推荐给距离它最近的那批种子用户。

## 7.1 训练 (Training) 与 推理 (Inference)

:::::::::::::: {.columns}
::: {.column width="50%"}
- **训练 (Training) - 模型参数构建**
  - 高投资、长时间、高能耗闭环计算
  - 摄取并处理海量互联网数据集
  - 参数结构剧烈变化定型
- **推理 (Inference) - 模型应用与预测**
  - 低成本、瞬时延迟运算
  - 对输入指令瞬间给出反馈回答
  - 适配边缘设备及普通服务器
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
如果把 AI 当作一个高考应届生，“训练”和“推理”就是它人生的两个阶段：

* **训练 (Training)**：就是**“模型参数构建”**。你需要花几千万美元买几万张顶级显卡，耗时几个月，把全世界能找到的海量的互联网数据集输入到模型中。在这个过程中，它的大脑结构（那几十亿个参数）在剧烈地改变和成型。这个过程**成本极高、耗电极大、且不能被打断**。比如 OpenAI 训练 GPT-4，就是在做这件事。
* **推理 (Inference)**：就是**“模型应用与预测”**。模型已经训练好了，毕业了，大脑结构固定了。现在你把它部署到公司的服务器里，给它输入一个指令（比如问它：“今天北京天气如何？”），它动用已经学好的知识，瞬间算出一个答案给你。这个过程**参数不会再改变，消耗的算力极小，几百块的普通显卡或者手机就能跑**。

**高管避坑指南**：如果有人建议：“我们要买1000张显卡在公司内部自己‘训练’一个大模型。”这种做法通常不符合成本效益；但如果是“我们买两台服务器在公司内部做大模型的‘部署和推理’，用来处理机务手册”，这是一笔具有较高投资回报率的方案。
:::

## 深度学习与强化学习

:::::::::::::: {.columns}
::: {.column width="50%"}
- **深度学习 (Deep Learning)**
  - 物理结构上的“层数多”（Layers）
  - 从初级特征逐渐组合到高层语义识别
- **强化学习 (Reinforcement Learning)**
  - 基于奖励与惩罚反馈机制的模型优化
  - 在无录像可供参考的高危/无数据环境中自主试错
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
“机器学习”大家都能理解，就是让机器从数据里找规律。那为什么要加个“深度”呢？**这里的“深”，指的是物理结构上的“层数多”（Layers）。**

在早期的 AI 里（比如识别一架飞机），我们只能建一层或两层简单的数学网络，它只能认出“这是一块金属”或者“这有一根翅膀”，特征提取能力受限。科学家们将这种数学网络叠了几十层、上百层！
* **第 1 层**：看懂了像素亮度的明暗；
* **第 10 层**：把明暗组合成了金属的反光和边缘的轮廓；
* **第 50 层**：把轮廓组合成了起落架和涡轮扇叶；
* **第 100 层**：网络高层最终完成了语义识别——哦，这是一架波音 737！
这种一层一层叠加提取特征，结构极深的神经网络，就叫“深度学习”。它是用计算深度的规模，换取了强大的特征表示能力。

我们刚才说训练就是给 AI 数据让它学。但如果有些任务，根本没有现成的数据怎么学？比如，你想让 AI 学会像王牌飞行员一样“在高空面对双发失效时迫降”。这不可能有足够的真实录像去教它。这时候就需要用到“强化学习”了。
**强化学习的本质，就是“奖惩反馈机制”。**

具体如何实现？你造一个一模一样的模拟飞行环境，把一个完全不懂飞行的 AI 扔进去，给它设定一个简单的目标（Reward）：**安全降落得 1000 分，坠毁扣一万分。**
* 第 1 次试飞，它直接推杆俯冲，坠毁，扣分。
* 第 100 次试飞，它学会了拉杆，但速度太慢失速，坠毁，扣分。
* 第 1 亿次试飞，它突然发现：“只要我保持 220 节的速度，放出 15 度襟翼，稳住下滑道，我就能得分！”

它就是在这种虚拟环境里，通过上亿次的自我试错、被惩罚、被奖励，硬生生“自己摸索”出了一套最优策略。当年打败人类围棋冠军的 AlphaGo，用的就是强化学习的技术。

好，扫清了这三个最大的概念障碍，大家再回想一下：无论是几万张显卡几个月的“闭关训练”，还是上百层的“深度网络计算”，还是上亿次的“强化学习试错”，这一切都指向了一个十分残酷的物理现实——我们需要前所未有的极限算力！这就回到了这章最核心的问题：当我们的模型有 270 亿个参数时，我们公司传统的 Intel 或 AMD CPU 服务器能胜任吗？答案是：**能干,但会慢到让你怀疑人生。**
:::

## 7.2 算力三剑客：定位与应用

:::::::::::::: {.columns}
::: {.column width="50%"}
- **CPU (王牌机长)**：极高单线程性能，擅长处理极小并发的复杂逻辑规则分支
- **GPU (地勤大军)**：上万核心规模，专精于逻辑简单但并发极高的大规模矩阵运算
- **NPU (专用传送带)**：阉割通用功能，极低功耗下专用于边缘设备的张量推理
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
在我们传统的认知里，中央处理器（CPU）是计算机的大脑，它无所不能。但最近几年，GPU（显卡）甚至 NPU（神经网络处理器）这些词铺天盖地。很多高管在采购设备时一头雾水：它们到底有什么区别？如果用我们航空业来打比方，这三者的定位泾渭分明：

**第一算力：CPU（中央处理器）—— 航空公司的“王牌机长”**
CPU 极其精密、复杂，单线程速度极快（主频高达 5GHz）。它能处理各种极其复杂的逻辑分支，比如处理机票预订系统的退改签规则、应对突发的特情。但是，王牌机长有一个致命缺点：**他只有一个人**（CPU 通常只有十几个到几十个核心）。如果你让这位高薪机长去停机坪上给 A380 搬运行李，他一次也只能搬一个箱子，这叫大材小用，效率极低。

**第二算力：GPU（图形处理器/显卡）—— 航空公司的“十万地勤大军”**
我们刚才讲的 AI 算距离、做矩阵乘法，是什么样的任务？这是一项**逻辑极其简单，但数量极其庞大**的任务。就是几百亿个数字两两相乘，没有复杂的 IF-ELSE 判断，全是纯粹的体力活。这时候，GPU 登场了。一块现代的英伟达 GPU（比如 A100）里面，密密麻麻地塞进了**上万个计算核心**！当几百亿次乘法任务砸下来时，CPU 是几十个机长在拼命算，而 GPU 是十万个只会算加减乘除的地勤大军，同时拿起算盘一起算。瞬间就能把一架 A380 的行李装满！这叫**大规模并行计算**。这也是为什么我们在云端训练大模型，必须抢购 GPU。

**第三算力：NPU（神经网络处理器）—— 专为搬行李定制的“全自动传送带”**
大家最近买新手机、或者采购所谓的 AI PC 时，一定听过 NPU（比如苹果的 Neural Engine）。它又是个什么东西？既然 AI 就是做矩阵乘法，那我们能不能造一个**只干这一件事、连屏幕画图功能都阉割掉**的绝对专用芯片？NPU 就是这条极其专用的全自动传送带。它干不了别的，但只要是算 AI 矩阵，它的效率极高，而且**功耗极低**（只要几瓦），所以它能被塞进你的轻薄笔记本里，在本地流畅运行 AI 而不发烫死机。

**总结一下：CPU 负责统筹全局，GPU 负责在云端提供高并发算力支撑，NPU 负责在终端设备上省电高效地跑 AI。**
为了让大家直观感受到刚才说的“十万地勤大军（GPU）”在面对海量简单计算时，到底比“王牌机长（CPU）”快多少，我们直接来看一段代码。

## 7.3 从向量到张量 (Tensor)

:::::::::::::: {.columns}
::: {.column width="50%"}
- **0维 标量 (Scalar)**：单一数值（如载重）
- **1维 向量 (Vector)**：一维坐标系或特征值列
- **2维 矩阵 (Matrix)**：二维数据表（Excel级）
- **多维 张量 (Tensor)**：高维数据容器的核心统称（如 3维RGB图像矩阵）
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
在聊 GPU 具体是怎么算之前，我要给大家引入一个在 AI 行业里天天被挂在嘴边，听起来十分高大上的词——**张量（Tensor）**。很多高管听到这个词会觉得高深莫测，其实，它的概念非常清晰明了。

大家还记得我们前面讲过的概念吗？
* **标量（Scalar）**：就是一个数字，比如飞机的重量 40 吨。它是 **0 维**的。
* **向量（Vector）**：是一排数字，比如一篇博客变成的 1024 个特征值。它是 **1 维**的。
* **矩阵（Matrix）**：是由向量堆叠而成的表格，就像 Excel 表格。它是 **2 维**的。

那么，当数据的维度突破了 2 维，变成了 3 维（像一个魔方立方体）、4 维甚至更高维度时，我们该叫它什么？数学家们为了省事，给所有这些多维的数据容器统称了一个名字：**张量（Tensor）**。

实际上，标量是 0 阶张量，向量是 1 阶张量，矩阵是 2 阶张量。一张 RGB 彩色图片，就是一个 3 维张量（宽度 × 高度 × 红绿蓝 3 个颜色通道）。如果你一次性把 32 张彩色图片打包喂给 AI，这个数据包就是一个 **4 维张量**。

在大语言模型内部，数据在神经网络的每一层之间流动（Flow）时，正是以高维张量的形式存在的。这也是为什么谷歌开发的深度学习框架，被命名为 **TensorFlow**（张量流）的原因。你的显存里塞得满满当当的，就是几十亿个数字排列成的高维张量。
:::

## 7.4 硬件加速：把乘法表刻在基因里

:::::::::::::: {.columns}
::: {.column width="50%"}
- **通用计算 (CPU)**：按指令顺序逐步运算，过程漫长
- **硬件固化 (Tensor Core)**：将高维张量矩阵乘法直接固化为硅片上的物理电路
- **效率跃升**：无需指令读取耗时，数据流入即瞬间完成跳跃反馈
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
在大家惊叹于刚才的速度时，我必须要指出一个很关键的细节。刚才演示的是图形渲染，也就是打游戏时显卡干的活。但在打游戏时，显卡调动的是光栅化单元和纹理单元。而我们今天讨论的 AI 计算，根本不是在画图，而是在做海量的"矩阵乘加运算"。那为什么大家不用专门的 AI 芯片，非要抢购英伟达的 GPU 呢？这就引出了科技界一个很核心的核心概念：**硬件加速（Hardware Acceleration）**。

为了让大家秒懂这个词，我们回忆一下小学数学。假设你现在是一个还没有背过"九九乘法表"的小学生。我问你：7 乘以 8 等于多少？你的大脑会怎么运转？你只能用最基础的加法逻辑去推演：你会把 7 放在心里，然后算 7+7=14，14+7=21……一直加 8 次，最后得出 56。这个过程很慢，需要耗费脑力走完一整套逻辑流程。这就好比传统的 **CPU 在算矩阵乘法**。它是通用芯片，没有捷径，只能用最基础的通用指令，一步一步地硬算。

但是，当你把"九九乘法表"背得滚瓜烂熟之后呢？我再问你 7 乘以 8 等于多少。你的大脑深处已经形成了**物理级别的神经元连接**，听到"七八"，你连一毫秒的思考都没有，直接条件反射般地吐出一个词："五十六"。这种把某种特定计算，直接固化成物理反射的机制，在计算机科学里，就叫做**硬件加速**。

英伟达的 CEO 黄仁勋做了一件什么改变世界的事呢？他敏锐地发现，全天下的 AI 科学家，底层全都在做同一种数学题：**高维张量的矩阵乘法**。于是，黄仁勋拍板决定：既然软件算太慢，那我们就直接在硅片上，用纯粹的物理电路，把大矩阵的"九九乘法表"给**刻**上去！这个专门刻在显卡硅片上、把复杂算术变成物理条件反射的硬件，就叫 **Tensor Core（张量核心）**。这也是为什么，目前除了英伟达，没有任何一家公司的显卡能如此完美地支持大模型。
:::

## 7.5 CUDA 护城河：十五年的孤注一掷

:::::::::::::: {.columns}
::: {.column width="50%"}
- **2006年的远见**：释放显卡通用计算潜能（Compute Unified Device Architecture）
- **2012年 AlexNet**：Ilya Sutskever 证明了消费级显卡在深度学习的巨大潜力
- **生态的绝对垄断**：
  - PyTorch, TensorFlow 均基于 CUDA 优化
  - 全球顶级推理引擎（vLLM）强绑定
  - 沉淀了无法迁移的研发"肌肉记忆"
:::
::: {.column width="50%"}
![](missing.jpg)
:::
::::::::::::::

::: notes
如果说 Tensor Core 是英伟达的"拳头"，那 **CUDA** 就是它的"神经系统"——没有神经系统，拳头再硬也打不出去。

时间回到 2006 年。当时，黄仁勋提出了一个想法：**把我们的 GPU 打开，让全世界的程序员不仅可以用它来渲染游戏画面，还可以用它来做通用的科学计算。** 为此，英伟达投入了巨额资金，开发了一套全新的软件平台——**CUDA（Compute Unified Device Architecture，统一计算设备架构）**。这套平台允许任何程序员用简单的 C++ 代码，就能直接指挥 GPU 里的上万个核心去做数学运算。该决定曾遭到无数同行的质疑和反对。那几年最艰难的时刻，黄仁勋在内部会议上反复说：“CUDA 不是可选项，它就是我们的未来。”

转折发生在 2012 年。多伦多大学的天才博士生 **Ilya Sutskever**（后来 OpenAI 的联合创始人）买了两块英伟达的**游戏显卡——GTX 580**，然后，他用 CUDA 在这两块消费级显卡上成功实现了具有突破性意义的 **AlexNet** 深度学习模型。全世界的 AI 科学家在一夜之间集体醒悟：**游戏显卡才是 AI 的终极武器！而唯一能拿来做深度学习的显卡，只有英伟达的——因为只有它有 CUDA。**

AMD 这时候才如梦初醒，匆忙推出了自己的竞品 ROCm。但为时已晚。从 2006 年到今天，英伟达在 CUDA 生态上的积累已经超过了 18 年：
* 全世界几乎所有的深度学习框架（PyTorch、TensorFlow）全都是针对 CUDA 编写的。
* 全世界最顶级的企业级推理引擎（vLLM、TensorRT-LLM）全部只在 CUDA 上运行。
* 几百万 AI 工程师的开发习惯已经深度绑定（`import torch`, `.cuda()`）。

这就是为什么在 AI 训练和推理市场，英伟达占据了绝对的主导份额。不仅因为硬件底座强大，更关键的是它的生态黏性。
:::

一开始，大家都被 ChatGPT 震惊了，我们在对话框里问它各种问题。
**遇到了什么坑？** 我们很快发现，大模型是一个“缸中之脑”。它的知识停留在它被训练好的那一天。另一个严重缺陷是，它会产生严重的“幻觉”现象。如果你让它查一下今天北京飞法兰克福的航班，它会一本正经地给你捏造一个起飞时间。

这十分考验 AI 对专业规则的遵守能力。请看屏幕，我们现场来和这个 AI 塔台对话试试。

## 阶段三与四：RAG 与 Skills 技术

:::::::::::::: {.columns}
::: {.column width="50%"}
- **RAG (检索增强生成)**
  - 作用：打破信息滞后，挂载企业内部知识库

- **Skills (功能调用 / Function Calling)**
  - 痛点突破：从“只读不写”升级至操作系统调度
  - 跨越：赋予大模型改变数字世界状态的执行能力（查天气、改系统票价）
:::

![](missing.jpg)
:::

::: notes
**阶段三：RAG (检索增强生成) —— 给先知发一张图书馆通行证**
**遇到了什么坑？** 咒语念得再好，也解决不了 AI 自身知识库滞后或缺失的问题。只要它的训练数据里没有我们公司的内部机密，它依然会捏造。
**怎么解决的？** 这就是我们在第五章给大家演示过的 **RAG 技术**。
我们不再指望 AI 记住所有知识。我们在它面前放了一个庞大的向量数据库（图书馆）。当飞行员提问“737 单发火警怎么处理”时，系统先去图书馆里把相关的几页飞行手册找出来，连同问题一起塞给 AI：“请严格依据参考资料进行专业回答。”
**RAG 彻底终结了 AI 在专业领域的幻觉问题，让企业敢于把 AI 用在严谨的规章制度上。**

**阶段四：Skills (技能调用) —— 给大脑装下手和脚**
**遇到了什么坑？** RAG 让 AI 拥有了阅读能力，但它依然**“只能看，不能动”**。如果我想让 AI “帮我把明天飞往巴黎的头等舱票价上调 5%”，RAG 根本做不到，因为它触碰不到我们的销售数据库。
**怎么解决的？** 行业引入了 **Skills（技能）** 或者叫 **Function Calling**。
我们将公司系统里一个个复杂的功能（查天气、改票价、发邮件）封装成“技能”。当用户提出需求时，AI 会自动输出一段代码指令：“我需要调用‘改票价’技能，参数是巴黎，+5%”。我们的业务系统收到指令去执行，再把结果还给 AI。
**这一步是历史性的跨越，AI 终于拥有了改变物理世界和数字世界的“手和脚”。**

## 阶段五与六：从失控的 AutoGPT 到严谨的 Workflow

:::::::::::::: {.columns}
::: {.column width="50%"}
- **AutoGPT (完全自治探索)**
  - 愿景：自主规划 -> 行动 -> 反馈循环
  - 风险：高风险的无序决策模式，极易陷入死循环或执行高危操作
- **Workflow (AI 工作流)**
  - 妥协：放弃自主规划，引入人类设计的节点控制
  - 效果：牺牲泛化能力，换取 100% 的企业级稳定性与可控性

**阶段五：AutoGPT 与失控的自动驾驶**
**遇到了什么坑？** 有了手脚后，人类提出更高的期望。能不能给 AI 一个宏大的目标，让它自己去规划、自己调用工具、无限循环直到完成？比如：“帮我策划一条飞马尔代夫的全新航线，并写好商业计划书。”
**怎么解决的？** 于是诞生了名噪一时的 AutoGPT。逻辑是让 AI 自己陷入循环：思考 -> 行动 -> 观察反馈 -> 再思考。
**但在实际商业应用中面临极高的系统性风险。** 如果你在 2024 年敢把 AutoGPT 接到公司的真实业务里，你会发现它就像一个高风险的无序决策模式。它随时可能在复杂的企业流程中陷入死循环，或者因为一个微小的逻辑偏差，把你数据库里的排班表全部搞乱。
完全的自治（Autonomous），在当时被证明是危险的。它很类似一个情景意识丧失的飞行员：飞行员想降落，降落需要放起落架。起落架放下后，1美元的指示灯坏了，AI会接下来浪费几十轮对话去调查这个指示灯，最后可能导致飞机失控。而如果它真的修好了指示灯，它早忘了自己是来降落的了。

**阶段六：Workflow (工作流) —— 严丝合缝的工厂流水线**
**遇到了什么坑？** 航空公司最怕的就是“失控”。我们绝不能接受一个 AI 客服在自动循环中突然给旅客退了一万张票。我们需要绝对的可靠和可控。
**怎么解决的？** 工业界做了一个伟大的妥协，发明了 **Workflow（AI 工作流）**。
我们不再让 AI 自由发挥了。人类架构师用连线图，画出严密的流程节点。
比如“行李延误索赔工作流”：节点 1（大模型提取行李单号）-> 节点 2（API 查询内部系统真假）-> 节点 3（规则引擎判断是否赔偿）-> 节点 4（大模型生成赔偿确认信）。
在这个模式下，大模型被拆解成了流水线上的一个个廉价工人，只负责简单的单一任务。**它失去了自由规划的权利，但换来的是 100% 的企业级稳定性。** 让人类牢牢掌控了方向盘。

那么，这些花了上千亿美元建数据中心的北美巨头们，到底想干什么？他们根据自己的历史基因，走出了截然不同的三条路。
**1. 微软与亚马逊：卖铲子与修铁路（平台赋能者）**
微软今年砸了 800 亿美元，深度捆绑 OpenAI，它的野心是把 AI 塞进你用的每一个 Office 软件和操作系统里。它想做 AI 时代的“水电煤”。而亚马逊（AWS）砸了惊人的 1000 亿美金。各位做航空运行的领导一定会对亚马逊的战略深有同感：亚马逊对内，利用强大的 AI 算法，极致压缩了它庞大物流网络的仓储和飞机调度成本（这正符合我们的业务需求）；对外，它不站队任何一家大模型，而是提供一个高度灵活的云底座，你想用谁的模型，我都给你提供算力。
**2. Meta (Facebook) 的阳谋：焦土战术（生态破坏者）**
Meta 走了一条最绝的路。它花了巨资训练出顶级的 Llama 大模型，然后，**免费开源给了全世界**。它的商业逻辑极具颠覆性：既然我在云计算上打不过微软和谷歌，那我就把“大模型”彻底变成免费的商品（Commoditize）！我釜底抽薪，摧毁你们收过路费的护城河。同时这些技术最终都会反哺 Meta 自己的核心利润池——精准的社交广告推送。
**3. 苹果的孤傲：绝对的隐私堡垒**
苹果的战略被明确定义为“为大众打造的 AI”。它坚持**端侧计算优先**，并首创了“私有云计算”。我们掌握着旅客高度敏感的身份行程数据。苹果向我们展示了示范：AI 不一定非要把数据传到云端给别人看。能够深度理解用户、同时做到“绝对不泄露隐私”的系统，才能赢得最高净值客户的信任。

**11.3 真相三：中国军团的“成本粉碎机”与非对称作战**
如果说北美巨头是在比谁的算力多、谁的电多，那么在遭遇高端芯片禁运的中国，科技企业们打出了一场具有革命性意义的“非对称战争”——**不拼规模，拼效率。**
中国军团不再执迷于堆砌虚荣的参数，而是致力于把顶级 AI 的价格打穿底线。
**阿里通义千问**：不仅全面开源，且极具普惠性；**深度求索（DeepSeek）**：在极度缺乏高端显卡的绝境下，这支团队用令硅谷瞠目结舌的底层架构创新，证明了“效率重于规模”。其旗舰模型性能匹敌一流闭源产品，但训练和推理成本仅为几十分之一。
它把原本高高在上的 AI“准入门槛”大幅降低了。这告诉我们企业一个极其重要的天大利好：**现在，高智商的 AI 已经处于极度普惠的成本拐点。**

**11.4 真相四：极低的用户黏性与传统行业“一夜被颠覆”的恐惧**
当我们看到大模型泛滥，背后隐藏着一个商业现象——**极其脆弱的用户黏性（User Stickiness）**。在今天面向用户的 AI 产品上，大多数人没有任何品牌忠诚度可言。大家都是“无脑追随最聪明的那个 AI”。仅仅因为某个 AI 在某个任务上“表现得更聪明一点”就能引发超级流量迁徙。
既然“高智商的 AI 能力”已经被 DeepSeek 们打成了极低价，随时可以被轻易获取，这就意味着行业的颠覆不再需要几十年的积累。
一旦你们的在线产品被新的竞争对手盯上，对方只要在其上叠加了一些基于最新一代大模型的、更聪明的 AI 交互体验（比如一分钟内用自然语言帮旅客从全联盟所有航班中规划出最具性价比中转方案的私人数字管家），原本忠诚于你们的高净值用户，可能一夜之间就大量流失了。
这也是为什么我们绝不能因为自己身处“传统实体行业”就掉以轻心，必须抢先武装。

**11.5 终局：从“对话聊天”到“雇佣数字员工 (Agentic AI)”**
综上所述，了解了算力、了解了巨头、了解了成本，最后，我必须向大家揭示 2026 年此刻正在发生的，最深刻的生产力突变。
你们可能觉得 AI 就是个对话框，像个高级百科全书。但今年，以 Cognition 公司的 Devin 为代表的技术，彻底重塑了人机交互。
我们正式进入了**“智能代理时代（Agentic Era）”**。
以前，你需要极其细致地“指导”AI 怎么做；现在，工作流变成了“异步（Asynchronous）”的。
你可以像对下属布置任务一样，对 AI 说：“去帮我排查一下今天所有延误航班的共性原因，比准天气数据，写一份报告发给运行总监。”
然后，你可以去喝咖啡了。这个 AI 代理会**自己**去查数据库，**自己**去网络上抓取气象记录，**自己**分析逻辑，遇到报错**自己**修复，直到把任务完成。
**人类与机器的协作模式，正式从“操控一件工具”，变成了“管理一个员工队伍”。**
