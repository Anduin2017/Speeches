## 早期人工智能：K-Means 算法

:::::::::::::: {.columns}
::: {.column width="50%"}
> "计算机不靠看，它靠算。"

$$d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$$

::: {.incremental}
- 计算机通过“算距离”理解相似性（欧氏距离）
- 盲蒙中心点，循环算距离
- 不断迭代寻找最佳分类聚落直到稳定
:::
:::
::: {.column width="50%"}
![](Pics/K_Means_Clustering_Algorithm_Steps.png)
:::
::::::::::::::

::: notes
但是，计算机没有眼睛，它看不到“两坨”点。那计算机要怎么把这些客户分类呢？这时候，一种古老、简单，但又可以说是早期“人工智能”代表的算法登场了——它叫 K-Means（K-均值聚类）。

计算机不靠“看”，它靠“算”。它计算什么？计算点和点之间的直线距离。

大家还记得初中学的勾股定理吗？在二维平面上，两个点 $(x_1, y_1)$ 和 $(x_2, y_2)$ 之间的直线距离（在数学上叫欧氏距离），公式是这样的:

$$d = \sqrt{(x_2 - x_1)^2 + (y_2 - y_1)^2}$$

计算机的做法简单粗暴：它先在纸上瞎蒙两个中心点，然后把所有的客户点都拿来算一遍距离。谁离中心点 A 更近，谁就归属 A 类；谁离 B 近，就归属 B 类。分完之后，它再根据分好的群体重新找更准确的中心点，再算一遍距离。循环几次，直到一切稳定下来。

结果你会发现，计算机通过这种死磕“算距离”的笨办法，最终得出的分类结果，和我们人类一眼看出来的“两坨”一模一样。

距离近的圈在一起，这就是计算机理解“相似性”的唯一方式。
:::

- 增加维度：餐食、航线、偏好...
- 千维空间：人类大脑无法想象
- 计算机：维度不是问题！
:::
:::
::: {.column width="50%"}
![](Pics/Machine_Learning_Terms_Embedding_Space_3D.png)
:::
::::::::::::::

::: notes
二维很好理解。现在，我们给这个坐标系加上一个 Z 轴，比如代表这个旅客的“年龄”。 $(x, y, z)$，这是一个三维立体空间，我们的点悬浮在了半空中。没关系，我们的大脑依然能想象出来，计算机也只需要在公式里再加一项即可。

接下来，我们需要进行一次逻辑上的推演。

如果我们再加一个维度，比如“偏好餐食（素食/肉食）”，再加一个“是否带小孩”，再加一个“常飞航线”，再加一千个、一万个描述这个旅客的特征……

到了四维、五维甚至一千维，我们人类的大脑就难以处理了，我们根本无法想象一个一千维的空间长什么样。**但是，计算机完全不care！**
:::

## 计算机眼中的“相似”

:::::::::::::: {.columns}
::: {.column width="50%"}
> 高维距离与低维数学本质毫无区别。

$$d = \sqrt{\sum_{i=1}^{n} (x_i - y_i)^2}$$

简化为向量的差的模（长度）：

$$d = \| \mathbf{x} - \mathbf{y} \|$$

::: {.incremental}
- 维度延伸：特征完美统一转化为向量
- 两向量差的模代表绝对的“相似度”
:::
:::
::: {.column width="50%"}
![](Pics/What_Are_Embeddings_Vector_Space.webp)
:::
::::::::::::::

::: notes
在计算机眼里，算 2 个数字的距离，和算 1000 个数字的距离，在数学本质上**没有任何区别**。它的距离公式无非就是变得更长了而已：

$$d = \sqrt{\sum_{i=1}^{n} (x_i - y_i)^2}$$

这个距离是两个点的欧氏距离。为了简化上面的公式，我们把它写成向量的形式：

$$d = \| \mathbf{x} - \mathbf{y} \|$$

可以看出，两个向量的距离，就是它们的差的模（长度）。这就是计算机理解“相似性”的方式。

:::


# 第四章：万物皆可向量
把文字变成数字

## 距离 = 相似度

::: {style="font-size: 1.5em; text-align: center; margin-top: 2em;"}
一切可以被转换为向量的东西，都可以进行计算。<br>
<br>
**“距离”就等于“相似度”。**
:::

::: notes
这个时候大家应该已经明白了，向量可以被计算机轻松聚类。如果我们把思维延伸到三维、四维、甚至一千维，在计算机底层的数学逻辑里，其实都是一样的。

既然如此，我们是不是可以得出一个惊人的结论：**一切可以被转换为向量的东西，是不是都可以使用这个操作？** 我们把现实世界的事物变成向量，然后让计算机去归类、去查询相似性、去进行逻辑推理……这就是初阶人工智能的基石！

在这个由向量构建的多维宇宙里，我们要确立一个绝对公理：**“距离”就等于“相似度”。**

无论是用户的喜好、文章的含义、还是图片的风格，只要我们在多维空间里计算出这两个“向量”的距离足够近，那在现实世界里，它们就是同一类东西。距离越近，灵魂越契合。计算机不懂什么是“喜欢”，不懂什么是“悲伤”，但它懂计算距离。
:::

## 4.1 给世界贴标签：博客文章的数字化实验

| 博客文章 | 空客 | 起飞 | 降落 | 波音 | 特征向量 |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **第一篇 (A320起飞)** | 1 | 1 | 0 | 0 | `[1, 1, 0, 0]` |
| **第二篇 (737降落)** | 0 | 0 | 1 | 1 | `[0, 0, 1, 1]` |
| **第三篇 (起降原理)** | 0 | 1 | 1 | 0 | `[0, 1, 1, 0]` |

$$ d_{1,3} = \sqrt{(1-0)^2 + (1-1)^2 + (0-1)^2 + (0-0)^2} \approx 1.41 $$

$$ d_{1,2} = \sqrt{(1-0)^2 + (1-0)^2 + (0-1)^2 + (0-1)^2} = \sqrt{4} = 2 $$

::: notes
为了让大家更直观地感受到向量的魔力，我们从最简单的手工打标签开始。假设在我们航空公司的内部知识库里，我刚刚写了三篇短小精悍的博客。

现在，我来给它们手工打上标签（Tag）：
第一篇讲的是 A320 的起飞，第二篇 737 的降落，第三篇飞机的起降原理。

假设我们的系统目前很简陋，一共只有 4 个维度的标签：空客、起飞、降落、波音。如果博客包含了这个标签，我们就记为 1，没有就记为 0。

按照这个规则，我们的三篇博客瞬间就变成了空间里的三个向量。看，文字消失了，取而代之的是纯粹的数字。我们可以实际计算一下第一篇和第三篇之间的欧氏距离，距离是1.41。第一篇和第二篇的距离是2，所以计算机得出结论：第一篇和第三篇更相似，跟人类直觉完全一致。
:::

## 4.2 欧氏距离的致命漏洞

如果此时混入一篇完全不搭嘎的第四篇文章：“**炒方便面**” `[0, 0, 0, 0]`：

<br>

$$ d_{1,4} = \sqrt{(1-0)^2 + (1-0)^2 + (0-0)^2 + (0-0)^2} \approx 1.41 $$

<br>

::: {style="font-size: 1.2em; text-align: center; color: red;"}
**荒谬的推论：A320起飞与起降原理的距离，竟然等于与炒方便面的距离！**
:::

::: notes
看起来很完美，对吧？但是，假设此时，我们的知识库里混进了一篇完全不搭嘎的第四篇文章：“炒方便面的做法”。它既没有空客，也没有波音，所以特征向量全是 0。

当我们算一下，第一篇（A320的起飞）和这篇（炒方便面）之间的欧氏距离：结果竟然也是 1.41！

这里存在一个明显的逻辑漏洞。第一篇和第三篇的距离是 1.41，第一篇和第四篇也是 1.41！如果计算机死板地依靠欧氏距离，它会十分愚蠢地告诉你：相关性是一模一样的！此时系统将完全不可用。

问题究竟出在哪里？

问题在于：**欧氏距离无法真正反映“相关性”。** 在欧氏距离的计算公式里，你因为“拥有一个不同的特征”所产生的距离，和你“缺失一个特征”所产生的距离，在数学上被等同对待了。这在处理高维稀疏特征时，是一场灾难。
:::

## 4.3 换个角度看世界：点乘与余弦

:::::::::::::: {.columns}
::: {.column width="50%"}
**向量点乘 (内积)**
<br>
把它俩相同维度上的数字两两相乘，然后再全部加起来。
<br><br>
**A320起飞** $\cdot$ **起降原理**
$1\times0 + 1\times1 + 0\times1 + 0\times0 = 1$
<span style="color: green;">有交集！</span>
<br><br>
**A320起飞** $\cdot$ **炒方便面**
$1\times0 + 1\times0 + 0\times0 + 0\times0 = 0$
<span style="color: red;">毫不相干！</span>
:::

::: {.column width="50%"}
**余弦相似度 (Cosine Similarity)**

$$ \mathbf{x} \cdot \mathbf{y} = \|\mathbf{x}\| \|\mathbf{y}\| \cos(\theta) $$

$$ \cos(\theta) = \frac{\mathbf{x} \cdot \mathbf{y}}{\|\mathbf{x}\| \|\mathbf{y}\|} $$

* $\theta = 0^\circ \Rightarrow \cos(0^\circ) = 1$ (绝对契合)
* $\theta = 90^\circ \Rightarrow \cos(90^\circ) = 0$ (风马牛不相及)
:::
::::::::::::::

::: notes
为了解决欧氏距离的致命漏洞，我们要回忆一下高中数学里的另一个核心概念：**向量的点乘（内积）**。

什么是点乘？最直白的理解，点乘就是把两个向量在相同维度上的数字两两相乘，然后再全加起来。

我们用点乘来重新审视一下刚才的三篇文章：
A320起飞 [1, 1, 0, 0] 与 起降原理 [0, 1, 1, 0] 的点乘结果是 1（结果大于 0，说明它们在某个维度上有共鸣，产生了交集！）
A320起飞 [1, 1, 0, 0] 与 炒方便面 [0, 0, 0, 0] 的点乘结果是 0（结果是 0，说明它们无论怎么乘，都激不起任何水花，毫不相干！）
看！仅仅换了一种简单的数学运算，炒方便面就被系统完美地踢出了局。

在高中数学里，两个向量的点乘，在几何上有一个优美的公式。把长度除过去，我们就得到了现代人工智能评估相似度最核心的公式——**余弦相似度 (Cosine Similarity)**。
只要我们抛弃绝对的直线距离，转而去计算**夹角余弦**，“炒方便面”的闹剧就永远不会发生了。
:::

## 4.4 终极技术：L2 归一化

::: {style="font-size: 1.2em; text-align: center;"}
**强行把所有向量的长度变成 1（投射到“单位超球面”上）**
:::

<br>

:::::::::::::: {.columns}
::: {.column width="50%"}
**第一，关于点乘**

把长度为 1 代入公式：

$$ \mathbf{x} \cdot \mathbf{y} = 1 \times 1 \times \cos(\theta) = \cos(\theta) $$

<span style="color: blue;">单位超球面上：点乘直接等于余弦！</span>
:::

::: {.column width="50%"}
**第二，关于欧氏距离**

运用余弦定理展开：

$$ d^2 = \|\mathbf{x}\|^2 + \|\mathbf{y}\|^2 - 2(\mathbf{x} \cdot \mathbf{y}) $$

$$ d = \sqrt{2 - 2\cos(\theta)} $$
:::
::::::::::::::

::: {style="margin-top: 1.5em; text-align: center; color: green;"}
**殊途同归：直线距离和旋转角度被完美地绑定在了一起**
:::

::: notes
讲到这里，大家可能会问：欧氏距离，夹角余弦，点乘。这三个东西在写代码时要切来切去吗？这不符合计算机的美学。于是，AI 工程师们施展了最巧妙的：L2 归一化 (L2 Normalization)。
既然向量的“长度”会干扰计算，那我们就强行把所有向量长度变成 1。这相当于把它们全拉伸投射到一个“单位超球面”的表面上。
我们看看实际效果：模长全是 1 后，点乘直接等于夹角余弦！而欧氏距离展开后也变成了 $d = \sqrt{2 - 2\cos(\theta)}$。
殊途同归！在完成了 L2 归一化之后，无论你是算点乘、算余弦相似度、还是算欧氏距离，在数学本质上已经是完全等价的了！这就是大一统。
:::

## 重新审视：“炒方便面”的彻底出局

在我们这个极简的 4 维模型（长度为 1）里：

- **A320的起飞** `[1, 1, 0, 0]` 与 **炒方便面** `[0, 0, 0, 0]`
- **点乘**: $1 \times 0 + 1 \times 0 + 0 \times 0 + 0 \times 0 = 0$

<br>
<div style="text-align: center; font-size: 1.5em;">
点乘直接等于 0！<br>
夹角 $\theta = 90^\circ$，$\cos(90^\circ) = 0$<br>
<span style="color: red; font-weight: bold;">它们没有任何交集，判定为完全不相关。</span>
</div>

::: notes
那炒方便面的事情解决了吗？
现在，我们用点乘来审判它：点乘直接等于 0！
这是因为两个特征向量在多维空间里完全垂直，夹角成了 90 度，毫无交集，被瞬间判断为完全不相关。干净利落。
但在真实的大模型中，由于捕捉标点和通用语法，极少出现绝对的正交，但距离依旧极其遥远。
:::

## 4.5 1024 维度的精细画像

如果我们将标签数量增加到 **1024 个可能维度**？

每一次查询，系统不再是简单的关键字匹配，而是在这 1024 维的宇宙中，寻找距离最近的一组坐标。

<br>

### Demo 3：演示 AI 把文本变成向量 (bge-m3)
| 文档 A | 文档 B | 余弦相似度 (Cosine) | 欧氏距离 (L2) | 机器得出的结论 |
| :--- | :--- | :---: | :---: | :--- |
| 第1篇 A320起飞 | 第2篇 737降落 | **0.6108** | 0.8823 | 弱相关 (勉强沾边) |
| 第1篇 A320起飞 | 第3篇 起降原理 | **0.6541** | 0.8317 | 同领域 (有交集) |

::: notes
我们把维度扩大。如果我们的博客系统拥有 1024 个维度的词库画像，搜索起落架故障时就不是找关键字，而是找距离最近的手册内容坐标。这就是早期搜索系统的原理。
但人工打标签太累，机器能自己找维度吗？完全可以。
Demo中使用的 bge-m3 模型，能自动把毫无标记的文字变成 1024 维的向量。
看这个表格：它计算的 A320 和起降原理的余弦相似度是 0.65 属于同领域，而炒方便面只有沾了点语法标点的 0.32。非常精准！

## 让异常无处遁形：安全走廊

不再需要几百条死板的 `IF-ELSE` 判断：

- 几十万个安全着陆航班的向量 $\rightarrow$ <span style="color: green;">粗壮的“安全走廊”聚类</span>
- 发生异常偏离的坐标 $\rightarrow$ <span style="color: red;">欧氏距离急剧变大触发报警</span>

<br>

> "不管处理旅客投诉、蒙皮划痕照片、还是万米高空的 A320，在底层算法看来，全都是一模一样的空间几何距离计算！"

**我们用一套数学逻辑，统一了整个世界。**

::: notes
为什么痴迷万物向量化？以前安全部抓“不稳定进近”，要写几百条互相干涉的死板规则。
但在高维空间里，我们把几十万个安全降落的航班扔进去，这些安全的向量点自然聚集成了一条“安全走廊”。当某次航班状态突变滑出边界（几何距离急剧拉大），系统直接就能报警。AI 根本不需要懂具体的物理规则。
这就是恐怖的威力，所有的东西底层全是同一个世界，统一为相似度的几何计算。
:::
